## Global Constraints

- `/api/positions` 行 schema **只增不改**：新增 `pe_ttm: number|null`，既有字段一律不动
- PE 只降级不报错：manual 资产与 GOLD_CNY_G 不请求（恒 null）；v7/crumb 失败 → null + log；请求失败绝不影响 positions 200
- crumb 流程：带 cookie jar 的 http.Client → `GET https://fc.yahoo.com`（404 属预期，取 cookie）→ `GET https://query1.finance.yahoo.com/v1/test/getcrumb`（带 UA）→ crumb 字符串内存缓存（mutex 保护），v7 返回 401/403 时重取一次再试一次，仍失败则 null
- Redis 缓存 `fund:<symbol>` 3600s，值为 JSON `{"pe_ttm": number|null}`（null 也缓存，防失败穿透）
- A 股 symbol 形态：`600519.SS`（沪）/`000001.SZ`（深），创建时统一 ToUpper 既有逻辑会把 .SS/.SZ 大写——Yahoo 接受大写后缀（实测验证）
- 单测：v7 响应解析 + crumb 重取逻辑用 httptest 覆盖；go build/vet/test 全绿无回归（portfolio 10、learn 无、quote 26+新增）
- 前端惯例：strict、e:unknown、`?? []`、tnum、卡片阴影、radix-nova 组件以 ui/ 实际导出为准
- 进程 PID 精确 kill 严禁 pkill；git add 显式路径严禁仓库根 add -A；smoketest/Smoke#2026；8080 若被用户占用用 PORT=8090 验证、不杀用户进程；conventional commits
